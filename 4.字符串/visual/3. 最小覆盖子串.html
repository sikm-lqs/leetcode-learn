3. 最小覆盖子串

返回 s 中包含 t 所有字符（含重复）的最短子串。

1. 题目理解

给定字符串 s 和 t，在 s 中找一个最短的连续子串，使它包含 t 中的每一个字符（包括重复字符，顺序无关）。若不存在返回 ""。

示例

输入：s = "ADOBECODEBANC", t = "ABC"
输出："BANC"
解释："BANC" 包含 A、B、C 各一个，且是最短的
ADOBECODEBANC
ADOBECODEBANC 首次覆盖："ADOBEC"（长度 6）
ADOBECODEBANC 收缩到最短："BANC"（长度 4）✅
关键概念：窗口是否「覆盖」t，取决于窗口内每种字符的数量 ≥ t 中对应需求量。用 valid 统计「已达标」的字符种类数，当 valid == len(target) 时即覆盖。

2. 核心思路：滑动窗口

用「右扩左缩」的滑动窗口框架：右指针负责找可行解，左指针负责把可行解优化到最短。

三个关键变量

  • target：t 中每种字符的需求量（如 {A:1, B:1, C:1}）
  • cur_window：当前窗口各字符的实际数量
  • valid：窗口中「数量已达标」的字符种类数
右扩：纳入 s[right]，若某字符数量恰好达标 → valid++
覆盖：valid == len(target) 时，窗口包含 t 的所有字符
左缩：在覆盖前提下不断左移 left，寻找更短解；移出后若数量不足 → valid−−
核心洞察：用 valid 把「窗口是否覆盖 t」的判断压到 O(1)。判达标用恰好等于（cur[c] == target[c]）才 valid++，避免同一字符重复累加；收缩时用严格小于（cur[rm] < target[rm]）才 valid--，因为移除一个后可能仍达标。

5. 详细过程模拟

以 s = "ADOBECODEBANC", t = "ABC" 为例。右指针扩张过程中共有 3 次窗口覆盖 t，每次都尝试左缩到最短。

第几次覆盖right 到达命中时窗口收缩过程最短答案
第 1 次5（C） "ADOBEC"（6） 移出 A → A 不足，失去覆盖 "ADOBEC"（6）
第 2 次10（A） "DOBECODEBA"（10） 连续移出 D、O、B、E、C，移出 C 时失去覆盖；期间长度均 ≥ 6 "ADOBEC"（6）不变
第 3 次12（C） "ODEBANC"（7） 移出 O、D → "EBANC"（5）更新；移出 E → "BANC"（4）更新；移出 B 失去覆盖 "BANC"（4）

第 3 次覆盖是关键：right=12（字符 C）后窗口 "ODEBANC" 覆盖 t，左缩时先得到 "EBANC"（长度 5 < 6，更新），再缩到 "BANC"（长度 4 < 5，再次更新），这正是「左缩求最短」的价值。

最终答案："BANC"（长度 4）✅

6. 代码逐段解释

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        # 统计 t 中每种字符的需求量
        target = {}
        for c in t:
            target[c] = target.get(c, 0) + 1

        cur_window = {}
        left = 0
        valid = 0                 # 已达标的字符种类数
        ans = ""
        ans_len = float("inf")

        for right in range(len(s)):
            c = s[right]
            cur_window[c] = cur_window.get(c, 0) + 1

            # 注意是 ==：恰好达标才 valid++，避免重复累加
            if c in target and cur_window[c] == target[c]:
                valid += 1

            # 窗口覆盖 t，尝试左缩到最短
            while valid == len(target):
                if right - left + 1 < ans_len:
                    ans_len = right - left + 1
                    ans = s[left:right + 1]     # 切片左闭右开

                remove = s[left]
                cur_window[remove] -= 1
                # 严格小于才 valid--：移除一个后可能仍达标
                if remove in target and cur_window[remove] < target[remove]:
                    valid -= 1
                left += 1

        return ans

target 字典：把 t 的需求压缩成计数表，窗口只需对齐这些计数。

cur_window[c] == target[c]：只有「恰好」达标的那一次才 valid++。若用 >=，同一字符超额时会多次加 valid，导致错误。

while valid == len(target)：只要窗口还覆盖 t，就持续收缩。len(target) 是 t 中不同字符的种类数（不是 len(t)）。

cur_window[remove] < target[remove]：移除左端字符后，只有当它的数量「掉到需求之下」才算失去覆盖，valid--。若仍达标，窗口继续覆盖，继续收缩。

ans 初值为 ""、ans_len 为 inf。若整个流程从未覆盖 t，ans 保持空串，自然返回 ""。

7. 复杂度分析

维度值说明
时间复杂度O(m + n)right 和 left 各最多遍历 s 一次（2m），建 target 遍历 t（n）
空间复杂度O(字符集)target 与 cur_window 最多存字符集大小（本题大写字母即 O(1)）
左指针看似在 while 里反复移动，但累计最多移动 m 次（从不回退），所以整体仍是线性，不是 O(m²)。

8. 常见易错点

错误：valid 用 >= 判断达标

必须用 cur_window[c] == target[c]。例如 t 需要 2 个 A，窗口从 0→1→2 个 A，只有到 2 的那一刻 valid++；若用 >=，第 3、4 个 A 还会重复加，valid 超过真实达标种类数。

错误：收缩时用 == 判断失去覆盖

移除字符后应判断 cur_window[remove] < target[remove]，而非 ==。因为之前可能超额（如窗口有 3 个 A，需求 1，移除 1 个后剩 2 仍 ≥1，不该 valid--）。

错误：valid == len(t)

应是 len(target)（t 去重后的种类数）。len(t) 是字符总数，含重复，会导致永远无法满足。

边界：无解

如 s="a", t="aa"，valid 永远到不了 need，ans 保持 ""，正确返回空串。

9. 总结

最小覆盖子串 解法精髓：

  • 右扩找可行：right 推进，纳入字符直到窗口覆盖 t
  • 左缩求最短：覆盖后持续左移 left，边缩边更新最短答案
  • valid 计数：用 == 计达标种类，把覆盖判断降到 O(1)
  • 时间 O(m+n)，空间 O(字符集)

💡 口诀：右扩找可行，左缩求最短；valid 数达标种类，等于 need 即覆盖。
