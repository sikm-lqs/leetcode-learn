1. 任务调度器

贪心调度 · 优先处理高频任务

题目描述

给你一个用字符数组 tasks 表示的 CPU 需要执行的任务列表，用字母 A 到 Z 表示，以及一个冷却时间 n。每个周期或时间间隔允许完成一项任务。任务可以按任何顺序完成，但有一个限制：两个 相同种类 的任务之间必须有长度为 n 的冷却时间。

返回完成所有任务所需要的 最短时间间隔。

示例：tasks = ["A","A","A","B","B","B"], n = 2 → 输出: 8
一种执行顺序：A → B → idle → A → B → idle → A → B

算法思路

贪心策略：优先处理数量最多、最难安排的任务，并尽可能用其他任务填满它造成的冷却空隙。

关键公式：

最短时间 = max(len(tasks), (maxFreq - 1) × (n + 1) + maxCount)
  • maxFreq：出现频率最高的任务的次数
  • maxCount：频率最高的任务有多少个不同的种类
  • (maxFreq - 1) × (n + 1)：最后一个高频任务前的框架长度
  • + maxCount：加上最后一轮的高频任务数量
时间复杂度：O(n) —— 统计频率 + 计算最大值
空间复杂度：O(1) —— 哈希表最多26个字母

核心亮点

  • ✓ 数学转化：将复杂的调度问题转化为简单的数学计算
  • ✓ 贪心思想：优先安排高频任务，其他任务填充空隙
  • ✓ 巧妙公式：通过框架分析得出最优调度策略

伪代码骨架

不模拟调度过程，直接按「出现次数最多的任务」搭框架：频率最高者决定最少轮数，其余任务填空位。


统计每个任务频率        # cnt[task] += 1
max_freq = 最高频率        # max(cnt.values())
max_count = 达最高频率的任务数 # sum(freq == max_freq)

框架长度 = (max_freq - 1 ) * (n+ 1 ) + max_count
return取两者较大值 # max(len(tasks), 框架长度)
关键字 变量 中文操作 注释公式
公式 (max_freq-1)(n+1) + max_count 是「最密集任务撑起的骨架」，若任务总数更大则说明冷却可完全打散，取 max 即可。

代码实现

def leastInterval(tasks, n):
    # 统计每个任务的频率
    cnt = {}
    for task in tasks:
        if task not in cnt:
            cnt[task] = 1
        else:
            cnt[task] += 1

    # 找到最高频率和最高频率的任务数量
    max_freq = max(cnt.values())
    max_count = sum(freq == max_freq for freq in cnt.values())

    # 计算最短时间间隔
    return max(len(tasks), (max_freq - 1) * (n + 1) + max_count)

算法详解

以 tasks = ["A","A","A","B","B","B"], n = 2 为例：

步骤1：统计频率

任务AB
频率33

步骤2：确定框架

  • maxFreq = 3（A 和 B 都出现3次）
  • maxCount = 2（有2个任务达到最高频率）
  • 框架长度 = (3 - 1) × (2 + 1) + 2 = 8

步骤3：填充框架

A → B → idle → A → B → idle → A → B
公式解析：
- (maxFreq - 1) 个完整周期，每个周期长度为 (n + 1)
- 最后一个周期加上 maxCount 个高频任务
- 如果任务总数大于框架长度，说明任务足够填满所有空隙，直接返回任务数

关键要点

  • 贪心核心：高频任务最难安排，优先调度
  • 框架思想：以高频任务为骨架构建执行框架
  • 边界情况：当任务足够多时，没有空闲时间，直接返回任务数
  • 应用场景：CPU任务调度、资源分配、排队系统等
